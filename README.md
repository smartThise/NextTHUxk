# OneTHU NextTHUxk — 下一代选课

`One App · One Identity · One Campus` · 选课工作台

</div>

> 清华本科生选课增强工具。在原选课页面叠加全屏工作台，提供课程搜索、课表预览、暂存管理、AI 排课等功能。

## 安装

> 🚀 校内访问 [git.tsinghua.edu.cn/gjl25/NextTHUxk](https://git.tsinghua.edu.cn/gjl25/NextTHUxk) 下载速度更快。
> 各渠道附件对照：`*.xpi` = Firefox 签名版（永久安装）；`*.zip` = Chrome / Edge / Firefox 手动加载通用包。

### Firefox：下载 xpi 一键装（推荐，永久生效）

1. 从 [Releases](https://github.com/smartThise/NextTHUxk/releases) 最新版本下载 `nextthuxk-<版本号>.xpi`
2. 打开 Firefox，地址栏输入 `about:addons`，将 xpi 文件**直接拖入页面**
3. 完成安装——该包经 Mozilla 官方签名，无需开发者模式、重启浏览器不失效

**Firefox 更新方式**：发布新版本时扩展会在页面上弹出更新横幅（也可手动到 Releases 页查看）。下载新版 xpi 后同样拖入 `about:addons`，会自动覆盖升级并保留全部本地数据（草稿 / 缓存 / 配置）。无需先卸载旧版。

### Chrome / Edge：解压加载

1. 从 [Releases](https://github.com/smartThise/NextTHUxk/releases) 下载 `nextthuxk-<版本号>.zip` 并解压
2. 浏览器打开扩展管理页（Chrome: `chrome://extensions`，Edge: `edge://extensions`），开启「开发者模式」
3. 点击「加载已解压的扩展程序」，选择解压后的文件夹

> .crx 直拖方式已被 Chrome 收紧拦截，不再提供。更新时下载新 zip 解压**覆盖原文件夹**后回到扩展管理页点击「重新加载」即可；若出现新旧实例冲突等诡异问题，先移除旧版再重新加载。

## 功能概览

### 课程浏览与搜索

- **随时查询架构（2.0 重构）**：不再整库预爬，搜索直达教务服务端按页取数，工作台秒开；关键词+筛选条件组合查询，分页条实时显示满足全部条件的页数与条数
- 全校课程目录搜索（按课名、课号、教师模糊匹配），**外校课全支持**：北大（PK/GPK）、北外（BW）等前缀课号可直接搜索、跳转定位，外校课真实上课时间自动解析进课表与冲突检测
- **可折叠筛选栏**：高级筛选收进按钮，课程展示区更大，展开状态自动记忆
- **搜索联想词**：边输边出候选，含 THU选课社区评分
- 按类型快速筛选：**必修 / 限选 / 体育 / 已选 / 我的队列 / 可选**
- 高级筛选：按**学分数**、**周几**、**第几大节**、通识课组、课程特色、本/研余量精确过滤
- **时间冲突筛选**：按与当前预览课表是否冲突过滤
- 每门课显示余量、竞争热度、各志愿排队人数

### 中签概率计算（预选阶段）

- 每门课程自动计算**所有合法选法的抽中概率**，红黄绿三色直观展示
- 概率模型基于志愿级联机制：容量按志愿优先级递减分配，结合各志愿报名人数估算中签率
- 课程卡片、暂存区、草稿列表、预览课表均显示概率信息
- 修改课程类型或志愿号后概率实时刷新

### 课余量实时数据（抽签结果阶段）

预选抽签结果出来后，系统自动切换到课余量模式：

- **实时课余量**：从教务系统获取所有课程的容量、剩余座位和排队人数
- **我的队列**：显示个人候补队列，包含队列排名和总排队人数（如「排队第121名 / 共185人」）
- 课程卡片显示余量/排队/排入希望值，替代预选阶段的概率显示
- 课表预览中候补课程显示排队状态，已选课程显示「已选」
- 草稿/暂存在课余量模式下也显示余量队列信息
- **志愿数据按教务检查点自动同步**（8:00 / 12:00 / 16:00 / 20:00），缓存信息条显示下次同步时间，无需手动刷新

### 时间冲突检测

- 所有课程卡片自动检测与当前预览课表（正选/草稿/暂存）的时间冲突
- 冲突信息直接显示在卡片上（如「⚠ 冲突: 周三3-4节 数据结构」）
- 支持筛选「仅无冲突」或「仅冲突」课程

### 选课 & 退选

- 课程类型选择遵循选课规则：必修课可选必修/限选/任选；限选课可选限选/任选；任选课只能任选；体育课只能体育
- 直接在卡片上选择课程类型和志愿号，点击「选课」提交
- 已选课程可**调整志愿顺序**（▲▼），系统自动校验志愿名额上限
  - 必修 / 限选 / 任选：1 志愿最多 1 门，2 志愿最多 2 门
  - 体育：1 志愿最多 1 门，2 志愿最多 1 门
- 3 志愿不限数量
- 操作后实时刷新选课状态

### 课表预览

- 自动生成已选课程的**周课表**视图（周一至周日 × 第 1-12 大节）
- 时间冲突标红显示
- 可预览暂存区或任意草稿的课表，一键切回正式课表
- 课表单元格显示课程名称和教师姓名
- **可直接在课表上操作**：鼠标悬停显示 ✕ 按钮，点击可退选（已选课）、从暂存移除、从草稿删除
- **点击课表课程 → 左侧定位**：自动清空筛选、按课号搜索并平滑滚动到对应课程卡，蓝框脉冲高亮（#23）
- **自定义时间占用**：课表预览标题栏「＋ 添加占用」可登记社团例会等课外活动（紫色显示），本地保存并**参与全部课程冲突检测**（#25）
- 暂存/草稿预览课表按概率着色（预选阶段：绿/橙/红；课余量阶段：显示余量/排队人数）

### 暂存课表（草稿）

核心创新功能：在不直接提交选课的前提下，预先编排多套课表方案。

- 将课程「暂存」到草稿区，**最多保存 5 张草稿**
- 暂存区每门课可独立调整课程类型和志愿号，实时显示所有选法的概率
- 已选课程也可一键转化为新的暂存草稿
- 草稿支持**展开查看全部课程列表**，可逐门调整类型/志愿或删除
- 「**提交选课**」：自动退选所有已选课，再按草稿内容一次性选入
- 提交后草稿保留，不会自动删除
- **导出 / 导入**：复制 JSON 分享给同学，对方导入后可直接提交
- 自动检测草稿内课程的时间冲突（含外校课钟点）
- **外校课时间记忆**：解析过的外校课时间本地持久缓存，导入他人课表 / 换学期后暂存与课表预览照常显示

### 培养方案检测

- 查看所有培养方案课组及完成进度
- 自动检测：已选课 + 暂存课 + 所有草稿是否覆盖方案要求
- 特殊规则：
  - 体育课互认：任一体育课可满足任意体育方案要求
  - 英语(3) 即「英语进阶读写」，可由「第二外国语」替代
  - 英语(1)(2) 即「英语阅读写作/听说交流(ABC)」，不可由第二外国语替代

### AI 排课

- 填入兼容 OpenAI 格式的 API 地址、模型名称和 Key
- **AI 课程搜索**：用自然语言描述需求，AI 在当前搜索结果中推荐并给出理由，一键暂存
- **AI 排课**：自动读取当前候选课程（含志愿统计、余量、外校说明）、已选课程、占用时段、所有暂存草稿与个人偏好
- **AI 搜索与 AI 排课均注入 THU选课社区评分/点评数据**，推荐理由参考真实口碑
- 生成推荐方案并自动存入暂存草稿区
- 对任选 / 通识课仅给出方向建议，不硬选具体课程

### THU选课社区评价（thubook.help）

- 课程卡片显示**社区评分徽章**（★4.6·12评），有点评的课才出现，点击看全部点评
- 点评正文**实时拉取**（星级 / 给分档位 / 时间 / 全文），永远最新
- 一键跳社区课程页或**去写点评**，反哺社区
- 全部流程 fail-soft：社区数据加载失败不影响任何选课功能

### 自动更新

- 定期检查 GitHub Releases 是否有新版本
- 发现更新时在顶部显示提示横幅
- 也可手动点击「检查更新」

### 学期管理

- 自动从教务系统 URL 检测当前选课学期
- 支持手动切换学期（点击右上角学期标签）
- 切换后自动清空缓存并重新拉取数据

## 2.x 新世代 — 革命性架构更新

**从 2026 年 3 月迭代到 2026 年 9 月，OneTHU NextTHUxk 迎来 2.x 新世代版本。**

相较于 1.x 版本，2.x 新世代进行了**革命性**的架构更新，并且修复了大量潜在的恶性 bug，也是 OneTHU 平台的统一调度架构首次实验。NextTHUxk 将作为 OneTHU 平台的首个官方插件推出。

### 架构更新

在 1.x 版本中，首次打开扩展需要调用教务系统 API 进行全校 6,000 余门课程的信息与志愿数据的全量爬取，丢包、缺漏现象极多并且耗时极长，后续的缓存命中时间也令人无法接受。

在 2.x 新世代中，**NextTHUxk 不再会对所有内容进行一次性全量爬取，而是采取更合理的随查随取。我们将根据用户的查询与选课情况随时调取教务系统 API，随时解析。实测工作台启动时间从 50s+ 提升到 5s 以内，工作台就绪时间不超过 10s。**

由于不需要命中缓存，**工作台的浏览器内存占用将缩小一半以上，占用扩展存储将下降到原来的 1/100。**

### 课程库解析更新

得益于架构更新，我们不再一次性爬取全部教务系统信息页，因此不再受到课程遗漏丢包的困扰。配合新加入的三次重试机制，截至目前，**2026 秋季学期本科生可选的 6,176 门课程全部可以在 NextTHUxk 进行查询，包括北京大学、北京外国语大学开放的互选课程。**

我们同时**完全重构了预览课表机制**。由于北京大学、北京外国语大学课程时间与清华大学课程时间无法完全匹配，我们直接将课表预览更新为**动态时间轴**，并且**完全支持外校互选课程的所有时间解析功能**。你可以在时间轴上自由添加占用、本校课程或外校互选课程，更清晰的预览内容。

我们修复了书院专项体育、航空体育、体育理论等**非全校统一体育课程**的解析错误问题。

### 2.1.0 课程身份与跳转定位修复（课序会骗人）

- **暂存概率错标根除**：暂存/草稿/课表预览概率按「课序+教师+时间」分层评分仲裁——课序精确且教师不矛盾 → 教师唯一直认 → 同师多课按时间消歧 → 分不出诚实缺省，绝不显示别人的数
- **跳转定位根治**：全部跳转入口（暂存/草稿/候补/课表预览）携带完整身份四参；未命中时池内已有数据直接渲染目标页并定位（页码 + 条目），配一次性保险丝防递归
- **概率自动回填**：暂存后不再要「点一下」才显示概率——池缺数据防抖自动爬全量补齐（每课号 2 次封顶）
- **加载全部真正生效**：旧版课号检索「加载全部」从未生效（护栏排序错误实锤），现 forceAll 优先 + 深页前缀过滤
- **全量降级守卫**：同查询浅层搜索结果不回写降级全量列表

### 交互更新

根据社区开发者的 PR，现在你可以直接在预览课表/暂存区/培养方案处点击任意课程条，即可跳转至该课程以及同课号下所有的课程，方便您筛选。

左边筛选栏现在可以收起，方便即时查看，减小视线遮挡。

### AI 辅助选课更新

我们依据全新架构更新了 AI 辅助选课接口。现在 AI 可以更准更快的提供参考了。**需要注意的是，由于选课决策本身是很复杂的规划问题，可能绝大多数大语言模型需要极长的时间推出建议。**

### 品牌更新

NextTHUxk 现在是 OneTHU 平台的官方插件部分，我们为其更换了 OneTHU 的品牌 Logo 与识别符号。未来会基于 OneTHU 平台推出更多更新，欢迎贡献，敬请期待。

## v2.0 随时查询（大版本重构）

> 架构级重写，与 [OneTHU](https://github.com/smartThise/OneTHU) 桌面版同源同款语义；品牌全面切换 OneTHU。

### 架构：随时查询

- **废弃整库预爬**：旧版启动要全量抓 300+ 页课程目录（慢且给教务压力）；2.0 启动只拉核心四路（已选 / 课余量 / 候补 / 培养方案缓存），课程数据按需向教务服务端分页查询——工作台**秒开**
- 服务端搜索完整移植 OneTHU 语义：课号/课名/教师/星期/大节/年级/通识课组/特色/本研余量组合筛选，中文参数 GBK 编码（UTF-8 直发会 0 行）
- **风暴护栏**：精确课号只探 1 页；总页数 ≤25 全量、>25 只探 5 页；「加载全部」显式补齐；页间错峰——绝不给教务制造 25 连发
- 本地叠加筛选（冲突 / 学分 / 文字说明 / chips）不再触发重查，分页条显示**满足全部条件的实际页数与条数**

### 外校课全支持（北大 / 北外…）

- 课号检索大小写修复（`BW3w0008` 此前被本地过滤误杀——根因实锤）+ 一级课表页签检索兜底（任选→限选→必修，教务 web UI 同款路径）
- 外校课真实上课时间在教务「选课文字说明」列：**自动解析钟点**进课表预览与全部冲突检测；解析结果持久缓存（换学期 / 导入他人课表不丢）
- 暂存 / 草稿 / 课表预览 / AI 全链路认外校课；多段课程志愿**绝不盲配**（按课序精确匹配）

### AI 选课助手升级

- **AI 课程搜索** + **AI 排课**双入口；候选集与界面所见同源
- 注入数据升级：志愿统计（各志愿报名/容量）、余量、外校说明列、占用时段（含自定义占用与外校钟点）、THU选课社区评分与点评节选

### 提交可靠性（选课 / 退选 / 志愿调整）

- **业务拒绝字典**：时间冲突、学分上限、先修不符等教务拒绝此前被当成功（假成功实锤），现明确失败并带出可读文案
- 未知响应不再假成功：轮询已选 / 候补列表确认后才下结论
- 排队二段提交使用响应页新 token（一次性 token 链，v1.3.12 血泪延续）

### 界面与品牌

- 品牌切换 **OneTHU**：插件图标、启动按钮、工作台左上角、Popup 统一 (One THU) 字标
- 可折叠筛选栏、动态分页条、构建徽章（面板可见，防旧构建疑案）、缓存信息条（含下次检查点时间）

## v1.3.12 链式 token 抓取（已回退）

> 用户诊断脚本破案：教务 UI 的翻页函数 `turn(p)` 就是普通表单提交 `page` 字段；但**每次翻页后页面刷新，表单携带服务器下发的新 token**。此前所有版本复用同一个 token 连续提交 300+ 次——Struts 式一次性 token 被复用后，服务器从第 N 次起返回空壳页（N 会漂移：294/181…）。这与 GET/POST、并发/顺序、节流全都无关，也解释了为何 UI 永远正常（每页新 token）

- **链式抓取**：每次翻页从上一响应的 HTML 中提取新 token 再提交，1:1 复刻 UI 行为
- 课程目录与课余量全部链式化；GET 兜底仅在链式完全失败时启用
- 抓全时 Console 明确输出 `catalog COMPLETE: 6078/6078`
- 响应中无新 token 时告警一次（兼作机制判定器）
